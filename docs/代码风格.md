# 代码风格

本文档由实际扫描本项目代码归纳（server：NestJS + TypeORM；admin：Vue 3 + Element Plus + Pinia），所有示例均取自真实代码。格式化由根目录 `prettier.config.cjs` 强制约束。

## 格式化规则

来自 `prettier.config.cjs`，全仓统一：

- 行宽 220（`printWidth: 220`），长调用、长对象允许写在一行，不做人为折行
- 单引号、无分号、尾逗号 `all`、2 空格缩进、箭头函数单参数带括号

```ts
// 一行写完长对象/长链式，不折行
@Column({ name: 'login_time', comment: '最后登录时间', type: 'varchar', length: 20, nullable: true, default: null })
loginTime: string
```

其他实际约定：

- `import type` 单独一条，与值导入分开写

```ts
import type { AuthType } from '@/types'
import { BusinessException, CommonConstant } from '@/common'
```

- Node 内置模块加 `node:` 前缀：`import { resolve } from 'node:path'`
- 路径别名：server 内部用 `@/common`、`@/utils`；admin 用 `@/api`、`@/types`、`@/utils`
- Vue 模板尺寸/布局用原子类（UnoCSS 风格）：`class="app-content flex h-full gap-16px"`、`w-240px shrink-0`

## 命名约定

### 文件与目录

server 按角色后缀命名，全 kebab-case：

```
user.controller.ts / user.service.ts / user.dto.ts / user.module.ts
xxx.decorator.ts / xxx.guard.ts / xxx.interceptor.ts / xxx.filter.ts
xxx.constant.ts / xxx.entity.ts / ajax-result.class.ts
```

admin：

```
api/system/user.request.ts          # 接口请求文件一律 .request.ts
store/modules/user.ts               # Pinia store
views/system/user/index.vue         # 列表页固定 index.vue
views/system/user/components/UserDialog.vue   # 弹窗/抽屉子组件 PascalCase
hooks/useConfig.ts / utils/tip-modal.ts
```

### 类与标识符

| 对象 | 风格 | 示例 |
| --- | --- | --- |
| 类 | PascalCase + 角色后缀 | `UserController`、`UserEntity`、`AllExceptionsFilter` |
| 常量容器 | PascalCase 对象，成员 SCREAMING_SNAKE_CASE | `RedisConstant.CAPTCHA_KEY` |
| 枚举 | PascalCase | `BusinessType.INSERT` |
| 变量/函数 | camelCase，完整单词不缩写 | `invalidationTasks`、`statusChangedToDisabled` |
| 私有成员 | `private readonly` 注入 | `private readonly userService: UserService` |
| store 导出 | `useXxxStore` | `useUserStore`、`useTagsViewStore` |
| 前端事件处理 | `handleXxx` | `handleQuery`、`handleDeptClick` |
| DTO 形参 | `xxxDto` | `create(@Body() createUserDto: CreateUserDto)` |

```ts
// server/src/common/constant/redis.constant.ts
export const RedisConstant = {
  CAPTCHA_KEY: 'captcha:img',
  ADMIN_USER_ONLINE_KEY: 'user:online',
}
```

### 类型

admin 接口类型按业务域组织命名空间，`types/api/system/user.ts` 内不写 `User.` 前缀，使用处通过命名空间访问：

```ts
// types/api/system/user.ts —— 文件内直接声明
export interface SysUser extends BaseEntity { ... }
export type UserForm = Partial<SysUser>

// 使用处
const queryParams = ref<User.UserQuery>({ pageNo: 1, pageSize: 10 })
```

## 代码组织与模块划分

### server

按「横切关注点 + 业务域」两分：

```
src/
├── common/            # 横切层：class/ constant/ decorator/ dto/ entities/
│   │                  #        exception/ filter/ guard/ interceptor/ middleware/ module/
│   └── index.ts       # barrel，全项目只从 '@/common' 导入横切设施
├── modules/
│   ├── system/        # 业务域，域内再分 feature
│   │   └── user/
│   │       ├── user.controller.ts
│   │       ├── user.dto.ts
│   │       ├── user.module.ts
│   │       └── user.service.ts
│   ├── monitor/  auth/  dashboard/  common/
├── shared/            # redis.service 等基础设施
└── utils/             # encryptPassword 等纯函数
```

- `common/index.ts` 是唯一出口，业务代码不深入 common 内部路径：

```ts
import { BusinessException, CurrentUser, DataScope, Operlog, PaginationPipe, RequirePermissions } from '@/common'
```

- 跨 feature 依赖走 Service 直注（`UserService` 注入 `DeptService`），不绕道 controller
- Controller 薄壳：只做装饰与委托，逻辑全在 Service

```ts
/** 新建用户 */
@Post('create')
@RequirePermissions(['system:user:create'])
@Operlog({ title: '用户管理', businessType: BusinessType.INSERT })
create(@Body() createUserDto: CreateUserDto) {
  return this.userService.create(createUserDto)
}
```

### admin

目录与后端模块一一镜像（`api/system/` ↔ `views/system/` ↔ 后端 `modules/system/`）：

- 列表页 `index.vue` 只管编排：搜索（ProSearch）、表格（ProTable）、分页（ProPagination）、弹窗子组件
- 弹窗/抽屉强制拆 `components/XxxDialog.vue`，通过 `defineExpose({ open })` 暴露，成功后 `emits('getList')` 刷新列表
- Pinia 一律 setup 风格：

```ts
export const useUserStore = defineStore('user', () => {
  const currentUserInfo = ref({} as Auth.CurrentUserInfo['user'])
  async function login(LoginForm: Auth.LoginParams) { ... }
  return { avatar, currentUserInfo, roles, permissions, login, getInfo, logout }
})
```

- `src/hooks`、`src/store/modules` 下的导出经自动导入插件全局注入，代码中直接调用 `useDict(...)`、`useAppStore()`，禁止显式 import；Vue/Pinia/Router 的 `ref`/`computed`/`watch` 等同理
- 请求层封装为静态方法类，一域一文件：

```ts
export class UserRequest {
  /** 新建用户 */
  static create(data: User.UserForm): Promise<string> {
    return request.post('/system/user/create', data)
  }
  /** 查询用户分页列表 */
  static findList(params: User.UserQuery): PaginationResult<User.SysUser> {
    return request.get('/system/user/list', { params })
  }
}
```

## 常用设计模式与惯用写法

### 装饰器声明式横切（server）

权限、操作日志、数据范围全部用装饰器挂在 controller 方法上，guard/interceptor 消费：

```ts
@Get('list')
@RequirePermissions(['system:user:query'])
@DataScope({ alias: 'user', userColumn: 'id' })
public findList(@Query(PaginationPipe) queryParams: QueryUserDto, @DataScopeSql() ds: DataScopeCondition) { ... }
```

### DTO 继承复用（server）

用 `@nestjs/mapped-types` 的 `PartialType`/`PickType` 组合，不复制字段：

```ts
export class UpdateUserDto extends PartialType(CreateUserDto) { ... }
export class ResetUserPwdDto extends PickType(CreateUserDto, ['username', 'password']) {}
export class QueryUserDto extends PaginationDto { ... }
```

### 实体基类 + toJSON 序列化钩子（server）

所有业务实体继承 `CommonEntity`/`BaseEntity`（公共字段 + createBy/updateBy 自动填充），时间字段在 `toJSON` 里 dayjs 格式化，只影响接口返回：

```ts
toJSON() {
  return { ...this, createTime: dayjs(this.createTime).format('YYYY-MM-DD HH:mm:ss'), ... }
}
```

含大写的属性名显式指定 snake_case 列名：`@Column({ name: 'dept_id', ... }) deptId: string`

### 业务失败直接抛中文异常（server）

不返回错误码对象，Service 内校验失败即 `throw`：

```ts
if (exists) throw new BusinessException('该用户已存在')
```

成功则返回中文字符串提示：`return '添加成功'`，由全局 `AllExceptionsFilter` / 响应拦截器统一包成 `{ code, message, requestId, data, timestamp, duration }`。

### 请求拦截器函数式注册（admin）

axios 实例创建后，各拦截器以函数形式依次挂载并注明顺序原因：

```ts
// 令牌刷新拦截器（须在响应错误拦截器之前，401 清场提示才不会被重复弹出）
tokenRefreshInterceptor(instance)
// 响应错误拦截器
responseErrorInterceptor(instance)
```

### 表格列配置化（admin）

ProTable 列用配置数组描述，插槽列只写 `slot` 不写 `prop`：

```ts
const columns: ProTableColumn<User.SysUser>[] = [
  { align: 'center', type: 'selection' },
  { align: 'center', prop: 'username', label: '用户账号', showOverflowTooltip: true, minWidth: 100 },
  { align: 'center', label: '状态', slot: 'status', width: 80 },
  { align: 'center', slot: 'action', label: '操作', fixed: 'right', width: 190 },
]
```

模板中用同名简写与 `useTemplateRef`：

```html
<ProTable ref="tableRef" :data :columns :hidden-column-keys ...>
<ProPagination :total v-model:current-page="queryParams.pageNo" v-model:page-size="queryParams.pageSize" @pagination="getList" />
```

### 弹窗组件三件套（admin）

`defineOptions({ name: 'Xxx' })` 紧邻 `<script setup>` 之下 → `open()` 由父组件经 ref 调用 → 成功后 `emits('getList')`：

```ts
defineOptions({ name: 'UserDialog' })
const emits = defineEmits<{ getList: [] }>()
async function open(record?: User.SysUser, defaultDeptId?: string) { ... }
defineExpose({ open })
```

### 工具类用静态抽象类（admin）

不需要实例化的工具集合用 `abstract class` + 静态方法，而非一堆散函数：

```ts
export abstract class TipModal {
  static msgSuccess(message: string, config: MessageOptions = {}) { ... }
  static msgWarning(message: string, config: MessageOptions = {}) { ... }
}
```

## 注释与文档风格

- 全中文，密度集中在「为什么/约束」而非复述代码
- 公共方法、实体字段用 `/** */` 单行 doc，实体基类用完整 JSDoc（`@description`/`@type`/`@example`）：

```ts
/**
 * TypeORM 通用实体基类
 * @description 封装所有业务实体的公共字段（主键、创建/更新信息、时间戳），避免重复定义
 * @abstract 抽象类，仅用于继承，不能直接实例化
 */
```

- 多步骤方法用编号行内注释：

```ts
// 1. 两次密码必须一致
// 2. 查询用户（仅查询id和密码）
// 3. 校验旧密码是否正确
```

- 非显而易见的坑位写行尾注释：

```ts
// 同名软删墓碑仍占用 username 唯一索引，先物理清理
```

- 常量对象逐项带用途说明（含键的拼接格式）；barrel 导出文件（`common/index.ts`）不加注释
- 注释中不标注来源出处，不出现「对齐 XX / 参照 XX」类表述，只写技术语义本身

## 错误处理方式

### server

- 业务失败一律 `throw new BusinessException('中文消息')`，交给全局 `AllExceptionsFilter` 统一转 JSON 响应
- Filter 里逐类归一化用户可见文案，最后兜底防空：

```ts
if (exception.name === 'ThrottlerException' || message.includes('status code 429')) message = '您的操作过于频繁，请稍后再试'
if (message.includes('foreign key constraint fails')) message = '当前数据关联其它资源，无法执行该操作'
return message || '服务器内部错误，请稍后重试'
```

- Service 各持一个 Logger：`private readonly logger = new Logger(UserService.name)`；开发/生产区分日志内容，异常附 `exception.stack`
- 安全/计数类组件 fail-closed：Redis 命令级错误显式检查并 `throw`，不做「异常返回 0」的静默兜底
- 多个独立异步收尾用 `Promise.all` 聚合（如批量清缓存、缓存失效任务数组）

### admin

- HTTP 错误统一由 axios 拦截器捕获并弹提示，页面代码不重复处理用户提示
- 页面内 async 函数的固定骨架：loading 置位 → 请求 → finally 复位；catch 里做类型收窄后记日志并继续 reject：

```ts
async function getList() {
  try {
    loading.value = true
    const data = await UserRequest.findList(queryParams.value)
    list.value = data.records
    total.value = data.total
  } catch (error: unknown) {
    const errMsg = error instanceof Error ? error.message : String(error)
    console.log('getList errMsg: ', errMsg)
    return Promise.reject(error)
  } finally {
    loading.value = false
  }
}
```

- 表单提交校验单行直调，不接返回值（validate 失败直接 reject 进 catch）：

```ts
async function handleSubmit() {
  try {
    await formRef.value?.validate()
    submitting.value = true
    ...
    TipModal.msgSuccess(isEdit.value ? '修改成功' : '新增成功')
  } catch (error: unknown) { ... } finally {
    submitting.value = false
  }
}
```

- 防重复提交用状态前置判断：`if (loading.value) return TipModal.msgWarning('正在查询中，请勿重复操作')`
